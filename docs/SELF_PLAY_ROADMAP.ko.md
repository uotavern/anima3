# Anima3: 자가 대전으로 실력을 높이는 전투 AI

작성: 2026-09-29. 이 문서는 구현 방향이며 신경망 강화학습의 완료 보고가 아닙니다.

## Pluto에서 확인한 것

[tscmoo/pluto README](https://github.com/tscmoo/pluto)의 설명에 따르면 Pluto는
자가 대전 강화학습으로 학습한 단일 신경망으로 Brood War의 전략과 유닛 조작을
수행합니다. 공개 저장소는 바이너리 배포용이며, 학습 코드·알고리즘·학습량은
현재 공개 자료만으로 확인할 수 없습니다. 따라서 그 구현을 그대로 이식하거나
같은 성능을 약속할 근거는 없습니다.

참고할 특징은 로컬 추론, 명확한 의사결정 주기, 상대별 오프닝 성적 기록입니다.
Pluto는 추론이 늦으면 게임 진행 자체를 늦출 수 있지만, 공개 UO 서버에서는
다른 이용자 때문에 그렇게 할 수 없습니다. Anima3에는 늦은 응답을 폐기하고
안전한 행동으로 이어가는 실행기가 필요합니다.

추가로 [실제 바이너리·가중치 분석](PLUTO_BINARY_ANALYSIS.ko.md)에서 모델 구조,
혼합 양자화와 행동 지연 검사 근거를 확인했습니다.

## 현재와 목표

| 항목 | 현재 | 목표 |
|---|---|---|
| 전투 조작 | 규칙과 시간 기반 주문·포션 절차 | 지연을 계측하고 중단·전환 가능한 실행기 |
| 전술 선택 | Jev와 로컬 Qwen이 playbook 선택 | 작고 빠른 로컬 전투 정책 모델 |
| 경기 간 적응 | 검증된 리플레이 요약을 다음 계획에 입력 | 경험으로 정책 가중치 갱신 + 상대별 전략 선택 |
| 상대 | 고정 scripted 상대 또는 동일 봇 | 이전 정책·서로 다른 스타일을 보관한 상대 풀 |
| 평가 | 10경기 작동 가능성 실험 | 학습과 분리된 고정 평가 및 버전별 승격 |

LLM/Jev는 경기 복기, 상대 스타일 요약, 훈련 과제와 전술 제안에 활용합니다.
포션의 초 단위 퓨즈와 주문 타깃 처리는 외부 모델 응답을 기다리지 않아야 합니다.
최종 정책 형태는 계측 후 정합니다. Pluto가 사용한 구체적인 RL 알고리즘을
추측해서 동일하다고 부르지 않습니다.

## 구현 순서와 통과 조건

### 1. 전투 실행을 안정화

- 관측·요청·타깃 수신·행동 전송에 단조 증가 시간을 기록합니다.
- 실행기는 주문 커서와 포션 커서를 구분하고 실제 퓨즈 여유를 확인합니다.
- 모델 계산 때문에 이미 진행 중인 시전·투척이 멈추지 않도록 프로세스와
  실행 주기를 분리합니다. 실제 p50/p95/p99 지연을 먼저 측정합니다.
- Weaken → Clumsy, Explosion + 포션 + Energy Bolt/Flamestrike를 작은 과제로
  검증합니다. 주문 시전과 적중을 구분하고 자해를 별도 실패 지표로 둡니다.
- 네트워크 지연·패킷 누락·적의 방해·긴급 회복을 포함해 완료/중단 사유를 남깁니다.

통과 조건: 동일 입력을 재생했을 때 타깃을 혼동하지 않고, 지연 시에도 외부
추론을 기다리느라 포션을 손에 쥐고 정지하는 현상이 없어야 합니다.

### 2. 학습용 환경과 데이터

- 별도 훈련 ServUO 인스턴스에서 초기화·종료·시드·룰셋·장비·경기장을 제어합니다.
- 공개 운영 서버의 시간을 변경하지 않습니다. 훈련 속도 향상은 분리 환경에서
  타이머와 전투 규칙의 동등성을 검증한 뒤 적용합니다.
- 정책 입력은 일반 클라이언트가 실제로 관측할 수 있는 정보로 제한합니다.
  상대 마나처럼 알려지지 않은 값은 unknown과 관측 시각을 유지합니다.
- 매 행동마다 관측, 가능한 행동 목록, 선택, 정책 버전, 실행 지연, 다음 관측,
  보상, 종료 여부를 기록합니다. 서버 리플레이 ID와 SHA256로 결과를 연결합니다.
- 타깃 지정·이동·시전·포션 사용은 합법적인 행동만 선택 가능하도록 제한합니다.

통과 조건: 같은 버전·초기 조건을 재현하고, 학습 입력에 상대의 비공개 상태가
섞이지 않으며, 중단된 경기와 정상 패배를 구분할 수 있어야 합니다.

### 3. 단계별 학습과 상대 풀

1. 사거리 접근, 생존, 주문 방해와 해제 같은 작은 전투 과제.
2. 사용자가 알려준 오프닝·연계 또는 유효한 플레이 로그로 초기 정책을 구성.
3. 고정 상대를 이기는지 확인한 뒤 과거 정책과 여러 스타일을 상대로 자가 대전.
4. 이전 상대들을 계속 섞어 최근 상대에게만 맞춘 정책이 되지 않도록 평가.

승패를 중심으로 보상을 구성하고, 보조 지표는 보상 악용 여부를 검사합니다.
상대에게 준 피해와 자해를 분리합니다. 무의미한 장기전·자해 후 회복 반복으로
높은 점수를 얻을 수 없도록 해야 합니다. 정확한 보상 계수와 학습 알고리즘은
환경 실측과 소규모 비교를 통해 정합니다.

### 4. 독립 평가와 공개 적용

학습을 멈춘 후보를 고정하고, 학습에 쓰지 않은 경기에서 기존 챔피언 및
다양한 상대와 비교합니다. 양쪽 출발 위치·경기장·시드를 균형 있게 배치하고,
승률뿐 아니라 자해, 투척 실패, 회복 실패, 판단 지연을 함께 평가합니다.
평가 중 실패한 후보를 통과할 때까지 같은 표본에 반복 시험하지 않습니다.
기존 `arena_learning.py`의 별도 평가·명시적 승격 원칙을 유지합니다.

## 현재 실험의 해석

진행 중인 10경기는 경험 기록과 다음 경기의 전술 변경이 연결되는지를
확인하는 예비 실험입니다. 신경망 가중치를 학습시키는 실행은 아닙니다.
5번째 경기에서 확인한 포션 자해 39점은 공격 피해에서 제외하도록 수정했고,
검증된 원본에서 경험 요약을 다시 계산했습니다. 원본 경기와 과거 모델 입력은
보존하고 수정 이벤트를 추가했습니다.

학습량·완료 시간·GPU 비용은 아직 추정하지 않습니다. 먼저 안정적인 경기 수/시간,
데이터 크기, 작은 정책의 추론 지연을 측정해야 합니다. 신규 유료 자원 생성이나
대규모 학습 작업은 이 문서 작성에 포함되지 않습니다.
