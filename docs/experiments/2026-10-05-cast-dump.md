# Cursor-clock cast dump timing

Worktree: `feat/cast-dump-timing`. This is a separate scripted timing probe;
original neural weights and the unfinished 100-match budget are unchanged.

## ServUO source findings

Inspected `arena-worktrees/servuo/Scripts/Spells/Base/Spell.cs` and
`MagerySpell.cs` (pre-AOS Magery):

- `GetCastDelay`: 0.5 + 0.25 * zero-based circle; `Cast()` subtracts 0.1s.
- `CastTimer.OnTick` sets `NextSpellTime = now + GetCastRecovery()` **before**
  `OnCast()` creates the target cursor. Pre-AOS recovery is 0.75s.
- `FinishSequence()` clears `Caster.Spell`; it does not reset recovery.
- Therefore a cursor held for the recovery period allows a new cast after
  target resolution. Waiting 0.75s again after targeting is unnecessary.
- Disturbance during casting instead uses `max(0.2, 1 - sqrt(elapsed / delay))`.
  The client lacks an exact server disturbance timestamp; the fast probe uses
  its conservative 1s upper bound after a disturbance, and backs off on a
  server recovery rejection. No spam/recovery bypass is implemented.

## Experiment

Three unrated one-round matches against the same scripted opponent, with the
same Explosion -> Energy Bolt -> Flame Strike selection loop and emergency
healing. Modes: `dump-baseline`, `dump-fast`, `dump-held`. This is one match per
mode, so not a reliable win-rate study. Interference, mana and emergency healing
can lengthen intervals; report exact spell pairs and sample counts.

Fast modes retain 0.75s from the **observed cursor**, finish acknowledged targets
without an extra loop, and choose the next action in the same iteration when
legal. Terrain radius is 4 rather than a full screen, with 10ms pumping rather
than 50ms; the spell sequence owns its cursor. Held mode releases Explosion only
after that recovery clock expires. Actual target acknowledgement still requires
cursor clearance AND mana expenditure; local optimistic cursor clear is not
accepted as server success. No target/cast flood or server edits.

45 tests passed including held cursor immediate follow-up, immediate-target
recovery, missing mana acknowledgement, disturbance guard, and prior cursor/
potion/live-collection tests. Source implementation is opt-in for probe modes.

Runtime `/opt/uoarena/anima3-cast-dump-20261005`, unit
`arena-cast-dump-20261005.service`, logs `.logs/comparison`.
Use `scripts/summarize_cast_dump.py LOG_ROOT` for server target-to-cast intervals,
client request intervals, RPC durations, verdicts and replay links. Server cast
events represent accepted casts; they are kept separate from request timings.

## Results and confirmation fixtures

All three comparison fixtures and two separate opening-confirmation fixtures
completed. The latter use Weaken -> Clumsy before the same held-cursor dump;
keep them separate from the original comparison because the opening changed.
Runtime `/opt/uoarena/anima3-cast-primed-20261005`, unit
`arena-cast-primed-20261005.service`. These five fixtures do not consume the
original 100-match experiment budget and produce no neural weight updates.

- Server Energy Bolt target -> Flame Strike accepted cast: baseline shortest
  1345ms (2 samples, other gap 6260ms); fast 807ms (1 sample); held 756ms
  (1 sample). Emergency decisions and interference can extend the interval.
- Observe RPC median: baseline 243.82ms, fast 62.72ms, held 67.96ms.
- Client Explosion target request -> Energy Bolt cast request: baseline
  1281.57/1326.31ms; opening-confirmation held runs 93.80/102.25/109.97ms.
  This is the delay **after release**; the held cursor deliberately pays the
  recovery before release. Do not claim a 90% reduction in the whole cast cycle.
- Server replay `0ca2c80de63648dca6909121a1e27bb1` shows accepted Explosion,
  Energy Bolt and Flame Strike casts, and two damage events of 36 and 38 within
  60ms. The other confirmation has 64 damage within 62ms. Anonymous damage
  events are not independently spell-labelled; these are observed damage bursts.
- The current server replay omits Explosion `spell_target` events. Its release
  interval is therefore reported from client wire logs, not invented as a
  server timestamp. Other spells retain server target-to-cast measurements.
- No recovering (502644) or already-casting (502642/502645) verdict was recorded
  in the five fixtures. Disturbance/fizzle still occurs and is retained in logs.
