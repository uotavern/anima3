# 10경기 전략 적응 실험

## 목적과 해석

첫 경기의 경험이 없는 Jev + 로컬 Qwen 에이전트가, 검증된 경기 결과를
다음 경기 계획에 반영하는 과정을 10경기 동안 관찰합니다.
상대는 같은 `standard` 전술을 유지하는 scripted 에이전트입니다.
모델 가중치를 수정하거나 공개 봇 정책을 자동 승격하지 않습니다.

고정되는 것: 상대 전략, 7GM/100·25·100 준비, 7x + EX potion 훈련 규칙.
학습 계정은 유지하고 도전자 자리는 매 경기 바꾸어 10경기에서 5:5로 배치합니다.
경기장은 서버의 빈 경기장 배정에 따르므로 보고서에 함께 기록합니다.
경기 결과의 무작위성과 경기장 차이 때문에 앞 5경기/뒤 5경기 비교는 참고용입니다.
통제된 고정 정책 평가나 유의한 승률 향상 검증을 대신하지 않습니다.

## 실행

서로 다른 훈련 전용 계정을 쓰며, 기존 경기 중에는 해당 두 계정끼리의
동일 훈련 규칙 경기만 종료를 기다립니다. 다른 상대·규칙이면 접속을 종료합니다.

```sh
# 계정 암호와 Jev API 키는 환경변수에 미리 설정
# SPAR_PASSWORD_A, SPAR_PASSWORD_B, TYPESAFE_API_KEY
python -m anima3.ten_duels \
  --user-a MY_TRAIN_A --user-b MY_TRAIN_B \
  --log-dir .logs/ten-live
```

기본 한도: 검증된 완료 경기 10개, 총 60분, 프로세스 시작 6회,
Jev 요청 600회, 로컬 LLM 계획 요청 100회. 재시작 시 이미 요청한 횟수를
로그에서 차감하고 같은 실험·상대·모델 설정인지 검증합니다.
통신 실패 등으로 확인하지 못한 경기는 결과를 만들어 넣지 않습니다.
실행 중 강제 종료 대신 종료 신호를 보내면 중단 상태를 기록합니다.

## 경기마다 남기는 증거

1. 서버 리플레이의 SHA256·경기 ID·참가자·규칙·완료 여부 검증.
2. 승패·피해·회복·시전·실패·포션 사용을 상대별 경험에 저장.
3. 다음 계획 요청의 `verifiedHistory`에 이미 완료된 경기만 포함.
4. 채택된 LLM 계획(`primary`, 조건별 `responses`, `reason`)과 Jev 전술 기록.
5. 경기 순서와 이전 전략 대비 변경 여부를 보고서로 작성.

파일:

- `ten-duels-state.json`: 실행기 진행/완료/중단, 시작 횟수
- `status.json`: 현재 접속/경기 단계
- `ten-duels-report.md`: 읽기 쉬운 경기별 결과와 리플레이 링크
- `ten-duels-report.json`: 경기별 계획·전술·자원 지표와 비교 집계
- `brain-0/strategy.jsonl`: 학습 에이전트의 계획/모델 판단 원본 로그
- `brain-0/opponent-memory.json`: 검증된 상대 경험
- `learning.jsonl`, `<match-id>/replay.jsonl`: 결과 감사 기록과 서버 원본

보고서는 각 실행 종료 시 갱신됩니다. 진행 중 수동 갱신:

```sh
python -c 'from pathlib import Path; from anima3.ten_duels import report; report(Path(".logs/ten-live"))'
```

확인 기준은 세 가지를 분리합니다:

- **실행**: 10경기의 서버 결과를 검증했는가?
- **적응**: 이전 결과를 계획에 사용했고 채택된 전략이 실제로 바뀌었는가?
- **성능**: 피해 차이·회복·승패 등에 어떤 변화가 있었는가? 10경기만으로 우월성은 미확정.
